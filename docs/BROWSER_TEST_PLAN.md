# План тестирования портала в браузере

Живой чеклист. Прогонять на проде после выкладки и дополнять, когда меняется поведение.

- Адрес прода: https://poker-tracker-ashy.vercel.app/
- Логины и пароли: [qa-accounts.local.md](./qa-accounts.local.md) (файл локальный, в git не входит)
- Аккаунты: **A** `qa-portal-a`, **B** `qa-portal-b`. Оба должны видеть только свои турниры.
- Локальный стенд `http://localhost:3000` использует ту же прод-базу. Осторожность та же, что на проде.

## Как обновлять

1. Новый сценарий — новый пункт в нужный блок, с ожидаемым результатом.
2. Устаревший пункт не удалять молча: пометить «снят» и дату, если сценарий больше не существует.
3. После прогона дописать строку в журнал внизу: дата, коммит (`/api/debug/version`), что прошло и что нет.
4. Пароли и user id править только в `qa-accounts.local.md`.

## Чего не делать

- Не входить в рабочие аккаунты с сохранёнными турнирами.
- Не создавать, не редактировать и не удалять турниры, имя которых не начинается с `QA-`.
- Блок «Запись данных» запускать только когда нужен. После него список QA должен вернуться к состоянию до прогона.
- Не менять режим Telegram-бота и админские настройки.
- Подсказка на `/auth` (`player@example.com` / `password123`) не является тестовым входом.

Имя турнира для блока записи: `QA-A-ГГГГММДД-ЧЧММ` или `QA-B-...`, площадка `QA-PORTAL`.

## Базовый прогон (без записи)

Отмечать прямо в копии прогона или в журнале. Ожидание для пустого QA: счётчики 0. Если на аккаунте остался свой `QA-` турнир с прошлого прогона, счётчик равен числу таких турниров, чужих названий нет.

### Сессия

- [ ] **B1.** Открыть `/auth` в чистой сессии (или после выхода). Форма «Вход», поля Email и Пароль, кнопка «Войти». Красного оверлея Supabase Admin нет.
- [ ] **B2.** Войти с заведомо неверным паролем аккаунта A. Остаёмся на `/auth`, есть сообщение об ошибке.
- [ ] **B3.** Войти аккаунтом A. Редирект с `/auth`. В меню пользователя имя `qa-portal-a`.
- [ ] **B4.** Меню → «🚪 Выйти». Попадаем на `/auth`. Повторный заход на `/tournaments` показывает «Требуется авторизация».
- [ ] **B5.** Войти аккаунтом B. В меню `qa-portal-b`, не данные аккаунта A.

### Свои турниры

- [ ] **B6.** Под A открыть `/tournaments`. Заголовок «Мои турниры». Числа «Всего турниров», «Общий бай-ин», «Общий выигрыш» считаются только по турнирам A. Чужих названий нет.
- [ ] **B7.** В поиске ввести строку, которой нет (`неттакого`). Текст «Турниры не найдены». Очистить поиск — список как в B6.
- [ ] **B8.** `/results` под A: счётчики турниров, побед, ITM, ROI и прибыли только по своим результатам. Чужих выплат нет. Пустой аккаунт: нули и «Результатов не найдено».
- [ ] **B9.** `/analytics` под A открывается («Аналитика и статистика»). Цифры не включают турниры другого пользователя.
- [ ] **B10.** Повторить B6 под B. Список B не совпадает со списком A, если у них разные турниры. У пустого B — нули.
- [ ] **B11.** `/settings` под текущим QA: в профиле его username (`qa-portal-a` или `qa-portal-b`). Сохранять настройки в этом прогоне не нужно.

### Доступ без сессии

- [ ] **B12.** В новой приватной вкладке без входа открыть `GET /api/tournaments`. Ответ 401, текст «Требуется авторизация», в теле нет списка турниров.
- [ ] **B13.** `GET /api/debug/version`: `vercelEnv` = `production`, записать `vercelGitCommitSha` в журнал.

### Страницы, которые открываются, но не про личные турниры

- [ ] **B14.** `/` без обязательного входа: карточки разделов и «Статус системы». Строка «База данных: Мок данные» — зашитый текст, не признак пустой или общей базы.
- [ ] **B15.** `/bankroll`: «Управление банкроллом», баланс `$2035`, в истории есть «Sunday Million». Это одни и те же мок-операции у любого аккаунта, не его банкролл. Форму «Добавить операцию» можно открыть; в базу она не пишет.
- [ ] **B16.** Пункт меню «OCR Демо» ведёт на `/ocr-demo`. Отдельной страницы сейчас нет — зафиксировать фактический экран (404 или иное) и не считать это падением изоляции.
- [ ] **B17.** «Войти через Google» на `/auth` показывает, что OAuth ещё недоступен. Вход QA при этом не ломается.

## Запись данных (только по запросу)

Делать под A, затем проверять B. В конце удалить созданное.

- [ ] **W1.** A → «Добавить турнир». Имя `QA-A-...`, площадка `QA-PORTAL`, бай-ин `1`, дата любая допустимая. После сохранения турнир есть в списке A, счётчик увеличился на 1.
- [ ] **W2.** Выйти, войти как B. Этого имени на `/tournaments` и `/results` нет. Счётчики B не изменились.
- [ ] **W3.** Снова A. Открыть созданный турнир, добавить результат (позиция и выплата любые небольшие). На `/results` у A виден этот результат и его сумма. У B по-прежнему нет.
- [ ] **W4.** A удаляет только этот турнир. В списке A его нет. Поиск по `QA-A-` пустой. B без изменений.
- [ ] **W5.** Если удаление не удалось — не трогать другие строки. Записать id и имя в журнал.
